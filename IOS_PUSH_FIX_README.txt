SAILOO - iPhone device token registration fix

Changed files
1. lib/main.dart
   Wait for APNs before requesting the FCM token on iOS (up to 10 seconds per attempt,
   with up to 3 delayed retries). Retry on iOS resume and token refresh. Prevent
   overlapping token requests; repeat after a page load that occurred during a request.
   Register after page completion independently of layout JavaScript.
   Keep the existing site/RegisterDevice endpoint and logged-in WebView session.
   Encode token form data and limit registration to the selected CRM host.
   Report permission, token readiness and HTTP status without printing tokens.
2. ios/Runner/GoogleService-Info.plist
   Added the supplied configuration unchanged. Bundle: com.cartzlink.bmapp.
   Firebase project: bornmarketing-sailoo.
3. ios/Runner/Runner.entitlements
   Added the APNs entitlement. The signed/exported app's provisioning profile
   determines development versus production; verify distribution signing in Xcode/CI.
4. ios/Runner/Info.plist
   Added Background fetch and Remote notifications modes.
5. ios/Runner.xcodeproj/project.pbxproj
   Added Firebase configuration to Runner's resource build phase, enabled capabilities,
   and connected Runner.entitlements for Debug, Release and Profile.

Required account configuration (cannot be verified from this project ZIP)
- Apple Developer > Certificates, Identifiers & Profiles > Identifiers:
  enable Push Notifications for com.cartzlink.bmapp.
- Refresh/regenerate the provisioning profile after enabling Push Notifications.
  If building with Codemagic, refresh the signing profile there as well.
- Firebase > Project settings > Cloud Messaging > iOS app configuration:
  upload the appropriate APNs authentication key (.p8) with its Key ID and Team ID
  if not already configured. This is required for push delivery; the plist alone
  does not configure Firebase-to-Apple authentication. Keep the key in the consoles,
  not in app source.

Clean archive notes
The build/app/intermediates directory is generated by Android builds. It is not
needed in a source ZIP. It will be regenerated by the next build and can grow again.
Use flutter clean after a build when you want to reclaim generated build space.
Do not delete source/configuration or signing files such as lib, assets, android,
ios, pubspec.yaml, google-services.json, GoogleService-Info.plist, key.properties
or the signing keystore. These project files are retained in this archive.
